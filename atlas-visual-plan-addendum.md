# Agent Atlas — дополнение к плану (v2)

## 0. Приоритет
Этот файл **заменяет** противоречащие места `atlas-visual-plan.md`. Что не упомянуто здесь — остаётся как в основном плане. Конфликты решаются в пользу этого файла. Заменяются:
- «Визуальная спецификация»: ярусы y и слоты `x=140+180×column` → раздел B.
- Шаг 7 (объектные SVG), Шаг 8 (раскладка), Шаги 10–11 (renderer, анимация) → разделы A, B, C, D.
- Правило «не сворачивать автоматически» → исключение для дочерних агентов (раздел C).
- Критерий «Canvas2D, без новых runtime-зависимостей» → раздел A.

Не меняется: backend-протокол Snapshot, lifecycle/stale/sleeping формулы, шаги 3–6 (кроме добавок C), камера/ввод (шаги 9, 11d), App shell (шаг 13), правила честности (нет выдуманного трафика, логотип только по metadata).

## A. Renderer: PixiJS вместо Canvas2D
1. В `frontend/package.json` добавить `pixi.js` (8.x, точная версия `--save-exact`, выпуск не младше 14 дней). Бандлится локально, никаких CDN.
2. Публичный контракт `SceneRenderer` из шага 11 **не меняется** (`setModel/resize/fit/focusNode/setReducedMotion/setVisible/destroy`, `RendererCallbacks`). `model.ts`, `geometry.ts`, `motion.ts`, `input.ts` остаются чистыми и не зависят от Pixi.
3. Соответствие: слои = `Container` (фон, острова, облака, рёбра, тени, узлы, значки, подписи, tooltip); глоу/облака/частицы — спрайты с `blendMode: "add"`; пылинки ≤64; рёбра — `Graphics`, перерисовка только при смене позиций; импульсы — спрайты вдоль кривой; подписи — `Text`/`BitmapText` с кэшем.
4. Один ticker. `setVisible(false)` → `ticker.stop()`; `true` → старт без накопления кадров. DPR ≤2 (`resolution`).
5. Перед кодом **прочитать API установленной версии** (типы в `node_modules/pixi.js`), не писать по памяти.
6. Если WebGL недоступен — понятное сообщение в сцене, не падение. Canvas2D fallback не делать.
7. Тесты: чистые модули — vitest (node). Playwright headless даёт software-WebGL: он годится для корректности/скриншотов, но **не для замера FPS**. FPS мерить в реальном браузере с GPU на целевом ПК, результат записать как есть.

## B. Кластерная раскладка (заменяет шаг 8, «слоты»)
Цель: естественные группы, живость, но детерминизм и отсутствие блуждания.

**Зоны (мягкие, не сетка).** Интернет-облако сверху; LAN и localhost ниже, у агентов; агенты — горизонтальная полоса в середине; кластеры проектов — основное поле под агентами. Высота мира вычисляется, а не фиксирована.

**Единица группировки — проект.** Кластер = плита проекта (центр) + её папки + файлы папок + инструменты своих агентов. Принадлежность папки/файла проекту: проект, чей cwd — префикс пути; иначе проект ближайшего обращающегося агента; иначе кластер «без проекта». Уточнить фактические связи по `graph.py` перед реализацией, не угадывать.

**Детерминированный случайный джиттер.** `rng = mulberry32(hash32(id))`. Все «случайности» — только из rng узла/кластера, никаких `Math.random`.

**Алгоритм** (чистая функция `layoutScene(nodes, edges, previous, pinned) → Map<id, Point>`):
1. Центры кластеров: сортировка по id, размещение по золотой спирали (угол `i×2.39996`, радиус `sqrt(i)×k`) с минимальным зазором `R_a + R_b + 40`; `R = 60 + 14×sqrt(memberCount)`.
2. Внутри кластера: проект в центре; папки по спирали Фогеля (`r = 34×sqrt(i+0.5)`, угол `i×2.39996 + jitter ±0.35 рад`, радиус jitter ±12%); файлы вокруг своей папки на радиусе `46 + jitter` с равномерными углами ±0.3 рад; инструменты — дуга вокруг своего агента.
3. Агенты: полоса агентов, x по близости к своему проекту; дочерние агенты — раздел C.
4. Коллизии: ≤60 итераций раздвигания кругов (зазор ≥ радиус_a + радиус_b + 24), порядок обхода по id, pinned не двигать.
5. **Инкрементальность:** если id уже есть в `previous` — позиция сохраняется. Новый узел появляется рядом с родителем (кластер/папка/агент) с джиттером, затем локальная коллизия только с соседями. Полная раскладка — лишь при пустом `previous`.
6. **Раскладка считается по полному snapshot.** Поиск/фильтры/focus только скрывают или приглушают, позиции не пересчитывают.
7. Переходы 600 ms ease-in-out для новых/сдвинутых, остальное как в плане.

**Живость (только визуальная, не меняет позиции модели):** парение ±3…6 ед., период 5…9 s, фаза от hash; лёгкий масштаб/оттенок по глубине слоя; «острова» под кластерами (спрайт `island`, вариант по hash, размер ∝ R); медленный дрейф слоёв облаков.

**Приёмка раскладки (юнит-тесты `layout.test.ts`):** детерминизм (два запуска → идентично); нет пересечений кроме pinned; добавление узла не двигает остальные; изменение search/filters не меняет позиции; fixture 200 узлов на 1080×1920 → `fitCamera.zoom ≥ 0.7`.

## C. Дочерние агенты: связь и сворачивание
**C1. Сначала разведка (read-only, без правок кода).** Найти в реальных JSONL OMP и Codex достоверное поле связи родитель→потомок (например, вызов инструмента запуска субагента с `call_id` ↔ id сессии потомка, либо явный parent id). Записать найденное. Если надёжного поля нет — связь **не угадывать** (ни по времени, ни по cwd); функцию оставить выключенной и сообщить.

**C2. Данные (если C1 нашла поле).** `GraphNode.data.parent_agent_id?: string | null`; ребро kind `"spawns"` parent→child; в адаптерах поле пишется в `agent.metadata` (без текстов). Билдер: защита от циклов; родитель не найден в snapshot → потомок корневой.

**C3. Связи при работе.** Пока потомок `active` — ребро `spawns` активно: три импульса parent→child по правилам плана. Нет активности — тонкая неактивная связь.

**C4. Сворачивание (клиент, чистая функция в `model.ts`).**
- `collapsed(child) = parent в сцене && child.status ∈ {idle, ended} && child.data.lifecycle_known === true && child не в expandedSet`.
- Потомок в `error`, `active` или с `stale` **не сворачивается**.
- Вложенность: счётчик потомков считается по всем уровням; отрисовываются только верхние развёрнутые.
- Свёрнутые не участвуют в раскладке; позиция = орбита родителя: радиус `parent.radius+22`, до 6 спутников, остальные в бейдже «+N». Видимая медленная орбита (reduced motion — статично).
- Переход 600 ms ease-in-out к орбите и обратно; повторный переход не перезапускается без смены состояния.
- Рёбра свёрнутого потомка к ресурсам перерисовываются от позиции родителя, alpha ×0.5, дедупликация по (parent, target).
- Клик по бейджу/спутнику → `expandedSet` +parent (UI-состояние в GraphView/App, не в backend). Выбор свёрнутого потомка из доступного списка раскрывает его группу. Поиск, нашедший свёрнутого, раскрывает и подсвечивает.
- Карточка родителя: «Дочерние агенты: N (M активных)».
- Все свёрнутые остаются в доступном списке (`role=button`) и в tooltip. Состояние выводится из snapshot, поэтому история воспроизводима.
- `SceneNode` расширить: `collapsedInto?: string`, `childCount?: number`.

**Допущение:** триггер — завершение работы самого потомка. Если нужен «завершилась сессия родителя», меняется только условие в `collapsed()`.

## D. Спрайты: растровые, сторонняя генерация
Промпты и процесс — в `atlas-sprite-prompts.md`.

1. **Логотипы провайдеров остаются векторными SVG из плана (шаг 7).** Их нельзя генерировать ИИ-моделью. Эмблема агента = сгенерированный пустой медальон + логотип поверх (отдельный слой).
2. **Объекты** (медальон, робот, проект, папка, файл, инструмент, глобус, острова) — PNG на плоском зелёном фоне `#00FF00`, вырезаются скриптом.
3. **Световые элементы** (облака, кольцо активности, дымка) — на чисто чёрном фоне, без альфы, рисуются `blendMode: "add"`.
4. **Скрипт** `tools/sprites/build_atlas.py` (Pillow, dev-инструмент, не входит в EXE): вход `art/raw/{key}__{variant}.png`; хромакей зелёного + despill; trim по alpha, отступ 4 px; ресайз по таблице размеров; premultiplied alpha; shelf-упаковка в атласы ≤4096²; выход `frontend/public/scene/atlas/objects.webp`, `fx.webp`, `atlas.json` (`key → {x,y,w,h,anchorX,anchorY,variant}`). Сырые файлы — вне `public/` (в `tools/sprites/raw/`).
5. **Размеры рантайма** (на DPR2): медальон/робот 256, остальные объекты 192, остров 384, облако интернета 1024×512, LAN/localhost 512×384, кольцо 256.
6. **Анимация — послойно**, не покадровыми генерациями: медальон (база / логотип / additive-кольцо); сквош/поворот из `sampleMotion`; вращение кольца при active; пульсация глоу; распад на 4 фрагмента (frame-субтекстуры); дрейф слоёв облаков; парение. Значки `z`, `!`, `✓`, `?` — векторные, чёткие, с глоу-спрайтом.
7. **Загрузка:** `loadSprites()` читает `atlas.json` + два атласа. Отсутствует ключ → процедурный запасной объект с тем же ключом и один `console.warn`; чужой бренд не подставлять.
8. **Приёмка артов (человек по скриншотам):** единый стиль и свет у всех объектов; нет текста/логотипов в сгенерированных объектах; чистые края без зелёной каймы; узнаваемость папки/файла без цвета; читаемость при размере 48 px.

# Agent Atlas — изометрическая живая визуализация

## Context
Пользователь просит существенно улучшить визуализацию, добавить собственные значки типов узлов и облако выхода в интернет над графом. Приоритет — красивая динамичная читаемая сцена, а не dashboard. План предназначен небольшой локальной модели: маленькие последовательные шаги, точные API и проверки.

## Подтверждённые визуальные решения
- Футуристическая изометрическая 2.5D-сцена; эмоциональный референс — «Первому игроку приготовиться», без копирования персонажей и брендинга.
- Вертикальная композиция: интернет сверху, агенты в центре, проекты/файлы снизу.
- Постоянные боковые панели убрать; управление и детали показывать по действию.
- Показывать все узлы; не сворачивать автоматически в агрегаты. Читаемость обеспечивать композицией, типовыми значками и состояниями.

## Дополнительные подтверждённые решения
- Основной экран строго портретный 1080×1920; целевая сцена 10 агентов / 200 узлов.
- Логотип агента обозначает достоверно известного провайдера модели, а не runtime; неизвестный — робот. Извлекать явные метаданные журналов, ручные назначения не добавлять.
- Папки/файлы — узнаваемые изометрические объекты файловой системы. Добавить отдельные файловые узлы.
- Интернет — верхнее облачное небо с отдельными сайтами; LAN — отдельное облако в форме сетевой эмблемы; localhost — отдельное облако-домик рядом с агентами. Локальная модель остаётся обычным агентом.
- Кривые световые связи с направленными импульсами. Имена всегда, кроме агентов с достоверным логотипом; длинные сокращать, полный текст по наведению.
- Цветовая атмосфера OASIS: тёмный мир, многоцветные объекты, cyan/розовые акценты. Фон — дымка и редкие световые частицы, без сетки.
- Активный агент: цикличная деформация/движение эмблемы как анимированный стикер; ожидающий: плавное дыхание; через 5 минут ожидания — отдалённый приглушённый сон с z z z, без удаления. Ошибка: однократное разрушение, затем повреждённая эмблема и !. Завершение: приглушённая эмблема с галочкой.
- Активность определяется жизненным циклом хода (генерация/инструменты → финальный ответ), не возрастом события. При пропаже телеметрии — отдельная серая метка «нет свежих данных», без выдуманного ожидания.
- Стабильная ручная камера; не блуждающие узлы, мягкое парение и появления. Карточка у выбранного узла, подробности в выдвижной панели. Одна постоянная кнопка меню; остальное скрыто.
- Максимальные эффекты при целевых 60 FPS; скрытая вкладка полностью останавливает анимацию.

## Approach: решения, общие для всех шагов


### Визуальная спецификация
- Мир `#080B19`, дымка `#162343`, текст `#EDF5FF`, cyan `#52E6FF`, pink `#FF67D8`, violet `#9F8BFF`, amber `#FFD27A`, error `#FF667D`. Проекты violet, папки amber, файлы голубовато-белые, инструменты pink, внешние адреса cyan. Логотипы сохраняют свои цвета; для монохромных использовать светлый `#EDF5FF`.
- Текст Segoe UI/Segoe UI Variable, 13 px при масштабе 1; имя максимум 22 Unicode-символа, затем …; полный текст в tooltip, DOM-карточке и accessible-списке. Подписи не скрывать автоматически. У распознанных логотипных агентов постоянной подписи нет, но tooltip/карточка показывают имя, модель и источник. У двух одинаковых эмблем — маленький порядковый номер, стабильный по сортировке agent.id.
- Базовая сцена 1000×1600 условных единиц, без CSS-поворота текста. Минимальные y ярусов: internet100, lan400, localhost590, agents780, tools990, projects1170, folders1360, files1530. Слоты x=140+180×column, column0..4; row0..N, y=origin+110×row. Internet-облако охватывает свои endpoint-строки плюс120px сверху/снизу. Каждый следующий origin=max(минимальный y этого яруса, последний занятый y предыдущего+160). При первоначальной раскладке/изменении набора id сортировать id и раскладывать заново по ярусам, pinned не двигать; при обновлении только статуса/метрик не перераскладывать. Изменение topology допускает один плавный переход600ms, не постоянное блуждание. Камера не перескакивает автоматически.
- Поддерживать все ориентации окна, основная приёмка 1080×1920; положение облаков остаётся сверху, а не боком. Если нужен широкий граф из тысяч старых сессий, сохранять все объекты, ручные zoom/pan и поиск, а не делать нечитаемо мелкие подписи обязательным начальным масштабом.
- Облако интернета — широкие перекрывающиеся полупрозрачные доли с тонким освещённым краем и дымкой, не рамка/карточка. Сайты — маленькие парящие глобусы внутри. LAN — узнаваемая схема из трёх соединённых точек в облачном силуэте; localhost — домик в мягком облачном объёме. Пустую сетевую зону не рисовать. Между агентом и реальным endpoint только реальные связи; декоративные облака не создают фиктивный трафик.
- Папка: янтарный контейнер с выступом и видимой боковой гранью. Файл: светлый лист с загнутым углом и маленькой надписью расширения (если известно). Проект: стек из трёх изометрических плит. Инструмент: полупрозрачный шестигранный модуль с ключом. Неизвестный агент: робот с глазами и антенной. Без emoji и замены файлов/папок одинаковыми кружками.
- Связи cubic Bézier: контрольные точки на 45% вертикального расстояния от каждого конца, при одной высоте дуга вверх на 60 единиц. Базовый stroke 1 px alpha .18; активный stroke 1.8 px alpha .75 и glow. Три импульса на активное ребро, период 1.8 s, движение строго source→target; эти импульсы означают наблюдённое направление ребра, не объём пакетов. Не анимировать неактивные рёбра.
- Работа: цикл 1.8 s, поворот эмблемы ±6°, squash/stretch до ±5%, подъём 4 px; не вращать непрерывно логотип вокруг оси. Idle: дыхание 4 s ±2% масштаба. Сон: alpha .35, scale .82, сдвиг вверх 18 px, три плавающих z с периодом 4 s; не закрывать соседей. Error: один раз за переход в error разбить эмблему clipping-ом на 4 фрагмента, сместить на 4..8 px за 450 ms, затем замереть с !. Ended: alpha .35 и ✓, без парения. Stale: отдельный серый ? и текст «Нет свежих данных», не менять семантический статус.
- Вход 320 ms ease-out, выход 240 ms ease-in; расположение новых/сдвигаемых узлов 600 ms ease-in-out, закреплённые не перемещать. Существующие позиции не пересчитывать по кадрам. Если topology не менялась, snapshot меняет только статусы/метрики. Анимации через единый requestAnimationFrame, не React setState каждый кадр.
- Glow и тени предварительно растеризовать на спрайтах/низком разрешении; не применять shadowBlur для каждого ребра на каждом кадре. Дымка — кэшированные радиальные градиенты, пылинки — не более 64. DPR ограничить 2. При hidden отменять RAF, при visible возобновлять без накопления пропущенных кадров. prefers-reduced-motion: без частиц, дыхания, распада и парения, статические значки состояний остаются.


## B. Кластерная раскладка (заменяет шаг 8, «слоты»)
Цель: естественные группы, живость, но детерминизм и отсутствие блуждания.

**Зоны (мягкие, не сетка).** Интернет-облако сверху; LAN и localhost ниже, у агентов; агенты — горизонтальная полоса в середине; кластеры проектов — основное поле под агентами. Высота мира вычисляется, а не фиксирована.

**Единица группировки — проект.** Кластер = плита проекта (центр) + её папки + файлы папок + инструменты своих агентов. Принадлежность папки/файла проекту: проект, чей cwd — префикс пути; иначе проект ближайшего обращающегося агента; иначе кластер «без проекта». Уточнить фактические связи по `graph.py` перед реализацией, не угадывать.

**Детерминированный случайный джиттер.** `rng = mulberry32(hash32(id))`. Все «случайности» — только из rng узла/кластера, никаких `Math.random`.

**Алгоритм** (чистая функция `layoutScene(nodes, edges, previous, pinned) → Map<id, Point>`):
1. Центры кластеров: сортировка по id, размещение по золотой спирали (угол `i×2.39996`, радиус `sqrt(i)×k`) с минимальным зазором `R_a + R_b + 40`; `R = 60 + 14×sqrt(memberCount)`.
2. Внутри кластера: проект в центре; папки по спирали Фогеля (`r = 34×sqrt(i+0.5)`, угол `i×2.39996 + jitter ±0.35 рад`, радиус jitter ±12%); файлы вокруг своей папки на радиусе `46 + jitter` с равномерными углами ±0.3 рад; инструменты — дуга вокруг своего агента.
3. Агенты: полоса агентов, x по близости к своему проекту; дочерние агенты — раздел C.
4. Коллизии: ≤60 итераций раздвигания кругов (зазор ≥ радиус_a + радиус_b + 24), порядок обхода по id, pinned не двигать.
5. **Инкрементальность:** если id уже есть в `previous` — позиция сохраняется. Новый узел появляется рядом с родителем (кластер/папка/агент) с джиттером, затем локальная коллизия только с соседями. Полная раскладка — лишь при пустом `previous`.
6. **Раскладка считается по полному snapshot.** Поиск/фильтры/focus только скрывают или приглушают, позиции не пересчитывают.
7. Переходы 600 ms ease-in-out для новых/сдвинутых, остальное как в плане.

**Живость (только визуальная, не меняет позиции модели):** парение ±3…6 ед., период 5…9 s, фаза от hash; лёгкий масштаб/оттенок по глубине слоя; «острова» под кластерами (спрайт `island`, вариант по hash, размер ∝ R); медленный дрейф слоёв облаков.

**Приёмка раскладки (юнит-тесты `layout.test.ts`):** детерминизм (два запуска → идентично); нет пересечений кроме pinned; добавление узла не двигает остальные; изменение search/filters не меняет позиции; fixture 200 узлов на 1080×1920 → `fitCamera.zoom ≥ 0.7`.

## C. Дочерние агенты: связь и сворачивание
**C1. Сначала разведка (read-only, без правок кода).** Найти в реальных JSONL OMP и Codex достоверное поле связи родитель→потомок (например, вызов инструмента запуска субагента с `call_id` ↔ id сессии потомка, либо явный parent id). Записать найденное. Если надёжного поля нет — связь **не угадывать** (ни по времени, ни по cwd); функцию оставить выключенной и сообщить.

**C2. Данные (если C1 нашла поле).** `GraphNode.data.parent_agent_id?: string | null`; ребро kind `"spawns"` parent→child; в адаптерах поле пишется в `agent.metadata` (без текстов). Билдер: защита от циклов; родитель не найден в snapshot → потомок корневой.

**C3. Связи при работе.** Пока потомок `active` — ребро `spawns` активно: три импульса parent→child по правилам плана. Нет активности — тонкая неактивная связь.

**C4. Сворачивание (клиент, чистая функция в `model.ts`).**
- `collapsed(child) = parent в сцене && child.status ∈ {idle, ended} && child.data.lifecycle_known === true && child не в expandedSet`.
- Потомок в `error`, `active` или с `stale` **не сворачивается**.
- Вложенность: счётчик потомков считается по всем уровням; отрисовываются только верхние развёрнутые.
- Свёрнутые не участвуют в раскладке; позиция = орбита родителя: радиус `parent.radius+22`, до 6 спутников, остальные в бейдже «+N». Видимая медленная орбита (reduced motion — статично).
- Переход 600 ms ease-in-out к орбите и обратно; повторный переход не перезапускается без смены состояния.
- Рёбра свёрнутого потомка к ресурсам перерисовываются от позиции родителя, alpha ×0.5, дедупликация по (parent, target).
- Клик по бейджу/спутнику → `expandedSet` +parent (UI-состояние в GraphView/App, не в backend). Выбор свёрнутого потомка из доступного списка раскрывает его группу. Поиск, нашедший свёрнутого, раскрывает и подсвечивает.
- Карточка родителя: «Дочерние агенты: N (M активных)».
- Все свёрнутые остаются в доступном списке (`role=button`) и в tooltip. Состояние выводится из snapshot, поэтому история воспроизводима.
- `SceneNode` расширить: `collapsedInto?: string`, `childCount?: number`.

**Допущение:** триггер — завершение работы самого потомка. Если нужен «завершилась сессия родителя», меняется только условие в `collapsed()`.
